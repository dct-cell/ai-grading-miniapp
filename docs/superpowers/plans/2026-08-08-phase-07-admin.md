# Phase 07 Admin Application Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a separated Admin web application for orders, aftersales, Workers, users, funds, configuration and audit without exposing Admin authority to mini-program credentials.

**Architecture:** FastAPI serves a dedicated /admin/api/v1 boundary with server-side opaque sessions, Argon2id passwords, HttpOnly cookies and CSRF tokens. A React/Vite SPA consumes only that boundary; every state-changing operation creates an audit event.

**Tech Stack:** FastAPI, Argon2id, SQLAlchemy, React, Vite, TypeScript, Vitest, Playwright

Add argon2-cffi>=25,<26 to project dependencies, reinstall editable project, and confirm old tests still pass.

- [ ] **Step 3: Implement sessions**

Hash passwords with PasswordHasher(type=Type.ID). Store only SHA-256 of a 32-byte random session token, expiry, last_seen_at and revoked_at. Set Secure in staging/production, HttpOnly, SameSite=Strict and Path=/admin. Rotate session token after successful login.

- [ ] **Step 4: Add CSRF**

Return a CSRF token from /admin/api/v1/auth/session. Require X-CSRF-Token on POST/PATCH/DELETE and compare in constant time. Origin must match configured Admin origin.

- [ ] **Step 5: Add rate-limit tests**

After five failed logins for one username/IP pair in 15 minutes, return 429. A successful login resets the username counter. Do not reveal whether a username exists.
